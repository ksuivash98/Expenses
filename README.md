# Личный финансовый кабинет

Автономное веб-приложение для учёта личных финансов. Работает полностью офлайн в браузере.

- Frontend: HTML5, CSS3, Vanilla JS (ES Modules)
- Данные: единое хранилище **LocalStorage** (`financeApp_v1`)
- Локальный режим без сервера; облачный вход и синхронизация через Supabase подключаются отдельно

## Быстрый старт

Откройте `index.html` в браузере или через локальный сервер:

```bash
npx serve .
```

По умолчанию приложение открывает локальный кабинет без входа. После настройки облака авторизация доступна через кнопку «Аккаунт».

## Первый запуск

Автоматически создаются:

- текущий месяц (финансовый период);
- стандартные категории бюджета (конверты);
- пустые списки доходов, расходов, кредитов, КУслуг и целей;
- настройки по умолчанию;
- запись в истории и приветственное уведомление.

## Хранение данных

Все данные хранятся в одном объекте LocalStorage:

```js
financeApp = {
  settings: {},
  currentPeriod: {},
  financialPeriods: [],
  income: [],
  budgetCategories: [],
  budgetTransactions: [],
  expenses: [],
  credits: [],
  creditPayments: [],
  utilities: [],
  utilityPayments: [],
  goals: [],
  notifications: [],
  history: []
}
```

После любого изменения данные сохраняются автоматически. Кнопки «Сохранить» нет.

## Денежный поток

1. Добавьте доход  
2. Распределите всю свободную сумму по конвертам  
3. Расходы, кредиты, КУслуги и цели списываются только из выбранного конверта  

## Периоды

Можно переключать месяцы, закрывать текущий месяц с переносом остатков по правилам конвертов, смотреть архив и сравнивать периоды.

## Установка приложения (PWA)

Откройте HTTPS-сайт и нажмите «Установить приложение», когда браузер предложит
установку. На iPhone: Safari → «Поделиться» → «На экран Домой».
Первый запуск требует сети; затем доступны офлайн-запуск и локальные записи.
Обновление загружается при подключении к сети. Закройте старые вкладки, чтобы
активировать новый service worker. Подпапка GitHub Pages `/Expenses/` поддерживается.

## Подключение облачного аккаунта

До подключения Supabase кабинет работает локально. Чтобы включить вход:

1. Создайте проект на https://supabase.com и выполните `supabase/schema.sql` в SQL Editor.
2. В Authentication → Providers включите Email и подтверждение email.
3. В Authentication → URL Configuration укажите Site URL и Redirect URL:
   `https://ksuivash98.github.io/Expenses/` (для разработки добавьте localhost URL).
4. В `cloud-config.js` укажите URL проекта и **публичный publishable/anon key**.
   Он будет виден в браузере. **Не используйте secret/service_role key.**
5. Отправьте конфигурацию в GitHub, зарегистрируйтесь, подтвердите email и войдите.
6. Для первого переноса старых записей: «Аккаунт» → «Перенести данные из локального режима».
   Исходная локальная копия сохраняется; действие доступно до создания облачного документа.

RLS разрешает чтение только собственного документа. Запись выполняется функцией,
проверяющей ID пользователя и номер версии. При конфликте синхронизация останавливается:
скачайте локальную копию, загрузите облачную версию, затем перенесите нужные записи вручную.
Автоматического объединения нет. Синхронизация запускается после правок, при возвращении
в окно и восстановлении сети. Реальная проверка сервиса требует настроенного проекта.

Данные разделены по ID аккаунта в LocalStorage. После выхода приложение возвращается
к локальному режиму, а копия аккаунта остаётся до следующего входа. На общем устройстве
после выхода удалите данные сайта в настройках браузера. Сессия хранится в LocalStorage:
это не шифрование данных и не защита от доступа к профилю браузера.

После настройки проверьте двумя аккаунтами изоляцию записей и на двух устройствах
сохранение и обработку конфликта. Для восстановления пароля пока используйте
инструменты администратора Supabase; отдельной формы восстановления в приложении нет.

Проверка интеграции: запустите сервер на localhost:3000, затем `python tests/cloud-smoke.py`
(нужны Python Playwright и Chromium в `/usr/bin/chromium`). API Supabase в тесте
имитируется; тест не заменяет проверку RLS и email на настоящем проекте.
